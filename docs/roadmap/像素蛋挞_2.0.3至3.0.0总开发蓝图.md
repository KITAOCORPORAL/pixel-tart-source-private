## 0. 文档状态

- 当前真实稳定基线：2.0.3
- 依据：源码版本、程序集配置、安装脚本、2.0.3 回传报告及现有安装包一致指向 2.0.3

## 1. 产品定位

像素蛋挞是面向摄影师的本地照片工作流中枢，不是预约、收入、客资、橱窗或团队经营后台。

目标主流程：

导入照片 → 建立项目 → 文件检查 → 查重 → 分组整理 → 客户选片 → 匹配 JPG/RAW → XMP/选片结果 → 批量处理 → 拼图/联系表 → 交付 → 归档 → 完整性检查 → 备份与迁移。

不可妥协的原则：本地优先、源文件安全、默认复制、默认不覆盖、默认不删除、危险操作先预览、长任务可取消、用户原片不静默上传。

## 2. 用户主要使用场景

1. 从客户返回的 JPG、TXT、CSV 或编号中提取选片结果，并匹配本地 JPG、RAW、XMP 和自定义格式。
2. 将拍摄项目按日期、相机、格式或人工分组，安全复制到新目录。
3. 批量压缩、水印、重命名、转档、删废片预览和 FTP 传输。
4. 使用模板快速制作拼图、长图、联系表和交付预览。
5. 对项目执行重复文件、缺失 RAW、文件夹差异和完整性检查。
6. 通过 XMP 与 Lightroom、Capture One 交换星级、颜色和选择状态，而不直接修改其数据库。
7. 生成压缩预览供客户手机选片，并将结果同步回本地原片。
8. 在本机运行质量辅助分析，只提供标记、分组和建议，不替用户删除。
9. 将项目、配置、模板和历史安全迁移到其他硬盘或电脑。

## 4. 当前技术债

### P0：进入下一版本前必须处理

1. **没有 Git 仓库**：无法可靠判断改动范围、建立版本分支、Tag、回滚点和不可变发布证据。
2. **发布目录未按版本隔离**：`artifacts/publish/win-x64` 与 `artifacts/installer` 为共享位置，存在覆盖同版本或跨版本混淆风险。
3. **主 ViewModel 过大**：`MainViewModel.cs` 约 2208 行，导航、设置、教程、许可、索引、匹配、复制、工具页和任务状态耦合。
4. **MainWindow 页面内联**：大量页面集中在一个 XAML 中，工具卡和固定操作难以复用、测试和无障碍校验。

### P1：2.1.0 前必须处理

5. **没有统一任务引擎**：当前只有单一 `CancellationTokenSource` 和 UI 状态，缺少队列、暂停、重试、持久化和恢复。
6. **没有文件操作事务/清单**：复制服务安全性较好，但没有执行前 manifest、目标校验、完成哈希和撤销记录。
7. **JSON 持久化没有 SchemaVersion**：设置、项目历史和索引使用单文件 JSON，缺少正式迁移、备份、恢复和并发写保护。
8. **日志无轮换和脱敏策略**：按天追加，但不限制总大小、保留天数，也未统一路径脱敏。

### P2：2.2.0 前必须处理

9. **无正式缩略图缓存**：已有 Cache 目录，但没有缓存键、尺寸变体、LRU、大小限制和损坏重建。
10. **测试结构偏静态**：大量 UI 测试读取 XAML/源码字符串，真实 WPF 交互、DPI、文件系统故障和端到端测试覆盖不足。
11. **手工依赖注入**：`App.xaml.cs` 直接创建全部服务，后续任务引擎、数据库、插件和云服务会增加启动耦合。

## 6. 每个版本功能边界

每个版本只允许实现表格中定义的核心目标。任何后续版本能力只能建立接口、数据契约或安全边界，不能在前一版本中以 Mock 页面宣称完成。每个版本发布后必须停止开发，等待用户明确验收。

2.0.4 应专注两项真实工具和快捷排序；2.1.0 再统一任务和文件安全；2.2.0 再引入数据库驱动的项目模板和健康检查。此顺序避免把大量文件操作继续堆入 `MainViewModel`。

## 8. 文件安全机制

现有可复用基础：`FileMode.CreateNew`、自动编号、防路径逃逸、写权限探测、磁盘空间预检、取消时删除部分输出、源文件只读打开。

路线图统一要求：

1. 所有文件修改前生成操作清单；
2. 默认复制，不默认移动；
3. 默认自动编号，不默认覆盖；
4. 移动、覆盖、永久删除必须二次确认；
5. 输出完成后校验大小，重要流程可选 SHA-256；
6. 记录源、目标、操作、冲突策略、开始/完成状态；
7. 部分失败不删除源文件；
8. 撤销前重新校验当前磁盘状态；
9. 外接盘断开、只读、无权限、磁盘不足必须可恢复地失败；
10. 所有测试只使用隔离数据。

## 9. 任务引擎架构

2.1.0 建立 `ITaskEngine`，任务状态至少包括 Pending、Running、Pausing、Paused、Cancelling、Cancelled、Failed、Completed、NeedsAttention。

任务由不可变定义、可恢复检查点和执行日志组成：

- 定义层：任务类型、输入、计划、输出、冲突策略；
- 执行层：受限并发、取消、暂停、重试、进度节流；
- 持久化层：SQLite 状态、步骤、检查点和错误；
- UI 层：右侧任务中心只订阅任务快照，不直接执行 IO；
- 恢复层：启动时识别未完成任务并让用户继续、回滚或放弃。

## 10. 项目数据库架构

建议在 2.1.0 引入 SQLite：

- `SchemaInfo`：SchemaVersion、CreatedAt、LastMigratedAt；
- `Projects`：项目身份、路径、状态、更新时间；
- `Sources`：来源目录、用途、优先级；
- `Selections`：客户输入和标准化编号；
- `MediaFiles`：索引元数据和来源，不存图像本体；
- `Tasks` / `TaskSteps`：任务和步骤状态；
- `OperationItems`：文件操作清单；
- `Templates`：项目和工作流模板；
- `QuickTools`：快捷布局；
- 后续增加 XMP、客户选片和 AI 结果表。

每次迁移前备份数据库；迁移失败时保留原库并进入只读恢复模式。

## 11. 缩略图缓存架构

2.2.0 前建立独立缓存服务：

- 缓存键：规范化路径 + 文件长度 + 最后修改时间 + 尺寸档；
- 尺寸档：列表、卡片、详情；
- 文件存储，不写 SQLite BLOB；
- SQLite 仅记录键、路径、大小、最后访问时间；
- 异步生成、受限并发、释放 Bitmap 和文件句柄；
- LRU 清理、总容量限制、用户手动清理；
- 损坏时删除单项并重建；
- RAW 优先读取内嵌预览，失败显示占位图。

## 12. 插件与外部软件桥接边界

当前没有插件系统。2.3.0 前只定义 `IPhotoMetadataBridge`、`ISelectionExportBridge` 和受控插件清单，不加载任意 DLL。

- Lightroom/Capture One 默认通过 XMP、文本清单和监视目录协作；
- 不直接修改 Lightroom Catalog 或 Capture One Session 数据库；
- 外部进程启动必须由用户明确操作；
- 插件必须声明输入、输出、网络、文件写入和版本兼容能力；
- 插件异常不得崩溃主应用。

## 13. 客户选片云端边界

2.4.0 必须先单独通过隐私和服务器评审。桌面端只上传用户明确选择的压缩 JPG 预览，可选水印；不得上传 RAW、原图、路径、日志、授权信息和其他项目。

服务端最小数据：匿名项目 ID、预览文件、选择状态、备注、有效期、提交版本。必须支持撤回、到期删除、访问最小化和同步冲突提示。

## 14. 本地 AI 边界

2.5.0 默认关闭并由用户主动运行。只做技术质量提示、相似组、构图和表情概率，不识别真实身份，不建立人物姓名库，不上传原片，不自动删除，不直接修改源文件。模型版本、置信度、硬件要求和数据删除入口必须可见。

## 15. 授权和商业化边界

当前 Provider=None，ProductId、PublicKey 和 PublicValidationToken 均未配置，不能宣称已连接生产授权平台。

免费版必须保留：防覆盖、冲突提示、操作预览、基础撤销、文件校验、本地分片、基础归片、基础整理和基础拼图。专业版可限制高级规则、无限项目、XMP、客户选片、队列、AI 和高级模板。

## 16. 测试策略

采用测试金字塔：

- 单元测试：解析、规则、冲突、路径、防覆盖、迁移；
- 文件系统集成测试：隔离目录、只读、权限、长路径、中文、断盘模拟、损坏文件；
- 数据迁移测试：每个 SchemaVersion 的升级、失败恢复和备份；
- 任务测试：暂停、取消、重试、崩溃恢复、幂等；
- WPF 结构测试：资源、无障碍、导航；
- 真实 UI 测试：深浅主题、100/125/150/200% DPI、1280/1600/1920；
- 安装测试：安装、升级、降级阻止、启动、卸载、用户数据保留；
- 端到端测试：项目建立到交付和归档。

现有 405 项测试可作为回归基础，但静态源码断言不能替代真实 UI 和文件系统故障测试。

## 17. 安装包与数据迁移策略

- 每个版本输出到 `artifacts/releases/<version>/`；
- 测试、UI、安装验证分别进入独立版本目录；
- 安装包文件名和版本不可覆盖；
- 生成 `release-manifest.json`，包含源码提交、版本、构建时间、文件大小、SHA-256、测试摘要；
- 用户数据保存在 LocalAppData，升级前自动备份关键 JSON/数据库；
- 新版本只执行前向迁移，不静默降级数据；
- 卸载默认保留用户数据，删除数据必须用户主动选择。

## 18. 回滚策略

1. Git 每个版本建立分支、合并提交和 Tag；
2. 发布产物不可变且保留上一版本；
3. 数据迁移前备份；
4. 应用启动失败时不继续写新格式；
5. 任务失败时保留清单和部分输出状态；
6. 更新失败恢复上一安装版本；
7. 回滚不覆盖用户原片，不删除未知文件。

## 19. 隐私原则

- 默认离线；
- 不后台扫描未选择目录；
- 不上传原片或 RAW；
- 日志和诊断默认不含照片、文件名、客户名、激活码和敏感设备标识；
- 诊断包和客户选片上传必须由用户主动确认；
- 网络功能显示目标、数据类型、大小、状态和删除入口；
- 所有云端功能可完全禁用。
