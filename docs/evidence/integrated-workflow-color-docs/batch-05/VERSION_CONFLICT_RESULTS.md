# 编辑版本冲突与跨库复制

主窗口向 ReferenceColorWorkspaceViewModel 注入 StudioVersionConflictDialog。窗口展示来源 Identity、仓储 Revision、本地/仓储参数快照及原因，提供重新载入仓储、将本地保留为新版本、取消。显示的是本轮真实冲突快照，没有修改原版本来伪造合并。

弹窗前写独立 .recovery-*.json，并 flush 到磁盘。取消保留当前会话和恢复文件。Reload 和 KeepLocal 都在选择后重新读 revision，再通过仓储 SaveAsync CAS；弹窗期间再次修改则拒绝并要求重试。KeepLocal 保留仓储原版本，复制不同的本地版本，保留名称、归档、调整参数与 OriginIdentity/OriginVersionId；重复同内容保留不会反复追加。

本批不开放参数字段自动合并。用户只能整份选择或保留为新版本，因而没有同字段平均或调整栈拼接。保留归档状态，即使本地与仓储同时改名/改参数，也可在新版本中完整保留。

跨库入口：选择目标 .ptlibrary→按内容 hash 查唯一素材→Resolver 验证→明确确认→再次验证双方文件→仅复制当前版本。源目录不改；目标已有相同来源版本时幂等返回；不同库全部历史不自动合并。

自动测试：两个工作区同时打开同一目录、仓储先改、保留本地新版本、窗口期间第二次变更拒绝、恢复文件存在；真实进程 version-prepare/update/stale 验证目录 CAS。跨库复制测试覆盖来源保留、重复复制、错误 hash 拒绝。保存会话时已改为冲突解决后重新采集目标状态，避免第二次会话写回旧参数。

桌面窗口可读性、滚动、窄窗和 DPI 未执行。恢复快照是可读 JSON，当前没有单独的历史恢复文件浏览器；原会话重开仍触发现有冲突流程。
