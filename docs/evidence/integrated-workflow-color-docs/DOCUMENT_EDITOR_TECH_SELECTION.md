# 策划文档编辑器技术选型

## 本批选择

第一步在现有 WPF `PlanningCenterView` 和现有文本持久化上增加结构化文本操作，不引入第二套应用或数据库。优点是兼容旧文档、改动小、可独立回退；它不是完整 Word 引擎。

## 候选比较

| 方案 | 编辑 | 分页/打印 | DOCX 往返 | 风险 | 决策 |
|---|---|---|---|---|---|
| WPF TextBox + 结构化文本 | 基础文本可靠 | 弱 | 无 | 功能上限低 | 当前增量方案 |
| WPF FlowDocument/RichTextBox | 中等富文本 | 有基础分页/打印 | 无原生高保真往返 | 序列化与复杂布局限制 | 可用于预览原型，不能宣称完整 Word |
| Open XML SDK | 非可视编辑器 | 不负责渲染 | 适合 DOCX 包读写 | 仍需编辑/布局引擎 | 后续 DOCX 服务候选，需先核对许可证和版本兼容 |
| 商业 WPF 文档组件 | 取决于产品 | 通常较强 | 通常较强 | 许可证、分发、.NET 10、长期维护 | BLOCKED：采购与技术验证未完成 |
| 自研分页布局引擎 | 可完全控制 | 可定制 | 需另做 | 成本和风险最高 | 不作为第一批 |

## 建议路径

1. 保留现有策划业务模型和纯文本兼容读取；
2. 新增版本化文档包，稳定引用 AssetId/ShotId；
3. 选定合法 DOCX 服务后做导入导出损失报告；
4. 分页编辑、打印和 PDF 使用同一布局树；
5. 高级环绕、修订和交叉引用后置。
