# Performance and lifetime interpretation

Measurements are cold pipeline calls unless explicitly noted. REAL_COLD_PATHS.json contains per-stage interval and elapsed time plus ledger, working set, private bytes and process peak. Stages: source hash; native legacy decode including its own source hash; orientation; current-edit rebuild; instant-only full-source scan; instant+HQ; native block; definition-reopen block; each format render/encode/built-in validation; extra decoded verification; output hash; final source hash. Overlapping pipelines MUST NOT be summed: instant-only is a separate diagnostic scan, HQ includes instant math, PNG/JPEG WriteAsync includes its own verification. Existing export callback does not isolate pure codec time; do not label combined write duration as pure encoding.

No cache-hit time is presented as cold performance. First legacy conversion now reuses the existing immutable native master rather than decoding again; a synthetic decoder-count assertion locks this behavior. Reopen/cache miss intentionally reconstructs. Source analysis for stacks without reference matching no longer allocates/quantizes a full RGB8 analysis image that no node consumes. Output float math/rounding and old decode options are unchanged; legacy full-render equivalence and entire regression suites are the gate.

Cancellation polls were added to the full RGB8 display adapter every8192 channel samples; the old parameterless method remains for binary/source compatibility. Edit loops already check tokens. Synthetic cancellation during large reconstruction must return within2s and release admission. LibRaw native calls cannot be forcibly preempted by this token and are checked at existing boundaries; this remains a latency limit, not hidden as immediate cancellation.

Initial real pressure observed a process peak above5GB while ledger was much lower. Final released-component figures are in REAL_WORKSPACE_PRESSURE.json. Do not infer an OS memory cap, no-leak proof, statistical improvement or benchmark speedup from these different runs. HeavyWork admission protects declared scratch/cache ownership, not every historical cache, native allocator or pending GC object.

Batch09 binaries remain local, but no controlled batch08/09 binary before/after timing was performed. This batch does NOT claim such a comparison. It reports final-path timings and exact same-source reference pixels only. Tests/builds may have run concurrently; these are diagnostic timings, not isolated benchmark certification.
