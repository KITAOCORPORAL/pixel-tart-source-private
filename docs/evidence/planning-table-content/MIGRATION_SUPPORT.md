# 摄影表格内容：迁移与支持矩阵

## 数据与兼容
沿用现有RTF正文 + PlanningRichLayout页面语义，不增加数据库schema、不改变镜头/资源身份。RTF保存图像嵌入、列表、合并格；Layout保存RepeatHeader及页眉等已有语义。R6编辑器代次隔离、草稿保存和检查器字段合并保留。

|能力|范围|验证|
|---|---|---|
|单元格嵌入图片|光标在单元格时“图片”入口插入InlineUIContainer；正文外保留原尾部图片块行为；画布快照保留原尾部身份处理|实际处理函数、撤销/重做、RTF重开；原生drawing+ImagePart；像素逐字节对比|
|项目符号/编号列表|已有“列表”及新增“编号列表”调用真实WPF编辑命令；十进制/Disc，单元格独立编号|按钮事件、一次撤销、StartIndex=3往返、独立numId|

|复杂列表项|每项一个段落+嵌套列表；未知MarkerStyle/非段落子块拒绝|不承诺任意Word列表/内容控件保真|

## 已修复迭代问题
- 多个单元格列表原先交错写abstractNum/num，违反OpenXML顺序；现所有abstractNum排在num实例前。
- RTF恢复后图片可能位于Span内；递归内联测试/导出，未用直接子节点计数掩盖丢图。
- 多行动作必须以LineBreak持久化和w:br往返；导回摄影投影比较统一CRLF/LF，避免24个假差异。
- 普通XamlWriter无法保存stream-backed bitmap，续表复制改XamlPackage。候选测量计入实际分页前段落和安全空间，断言每段一页，不用删除断言接受多余页。
- 重复运行XPS证据目录会已有DocumentSequence；测试每轮使用新Guid子目录，不读旧输出冒充新证据。

## 真实UI范围
沿用Grok开始/插入/布局的现有四组真实工具：图片入口按当前光标识别单元格；列表与编号列表接EditingCommands；不加未实现七页签。不是Grok像素级复刻。原r5差异仍保留，Windows焦点/选区/IME、物理DPI、WPS实际域更新与编辑NOT_RUN。
