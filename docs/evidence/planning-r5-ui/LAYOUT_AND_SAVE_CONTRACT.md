# 布局存储与保存合同

在PlanningDocument增加可选UiLayout；旧JSON缺失使用默认248/300和检查器显示。未改变FoundationVersion、ProjectId、DocumentId、ShotId、资源/正文/照片处理定义。Normalize钳制非有限/超范围宽度，CollapsedGroups按名称存储。

布局保存先走已有FlushAsync提交当前镜头单元格、结构/富文本和检查器实际变动；失败不改布局。随后UpdateDocument排入已有恢复草稿/原子写链路，成功后重开恢复宽度/折叠。窄窗自动收起是派生状态，不覆盖用户保存的桌面宽度。

检查器取消只撤销当前未提交表单；已经自动保存的其他内容不回滚。表格提交后再合并检查器变动字段；不重写没有改动的字段。新资源编辑仍在独立对象上验证，取消零写入。

抽屉使用同一真实控件在主栅格与overlay之间移动，关闭恢复原Grid.Row/Column，不复制第二套数据控件。宽度改变只影响策划模块。未新增全局快捷键；仅在本页处理Esc/Tab/搜索，输入控件自己的撤销保持原样。

实机焦点流仍需人工验收；离屏对象测试只验证可达控件、overlay状态、列恢复、保存及失败链，不声称前台键盘已测试。
