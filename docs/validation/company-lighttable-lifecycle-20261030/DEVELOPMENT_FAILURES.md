# 开发中发现与修复
- 同一测试新签名绑定旧产品导致MissingMethodException：保留原Prepare(CancellationToken)入口，基线测量使用反射绑定同签名重新跑。
- 滚动取消测试起初检查了被新请求覆盖的Token：改为保存旧请求Token再判断，确定性复跑PASS，非延长sleep。
- 1GiB临时准入过严，拒绝两张可支持RAF：改为既有全局资源账本尺寸估算，仍拒绝约2.89GiB超预算图，不提高2GiB门槛。
- 32卡限制会隐藏密集重叠项：冻结前移除，改为全部真正可见卡，标准100布局实现30卡。视区外移除仍有效。
- Fuji跨次hash不一致：旧完整decoder重复同样可复现；没有掩盖/修改LibRaw算法。单列OPEN。
- 家庭7失败缺公司源文件与native阶段，不伪造精确根因或成功复跑。完整旧失败/本次早期TRX日志保留在本机交付根，最终证据只选择明确通过的受影响测试。
