# 公司实测：客户选中的现场 JPEG，退出重开后能再次导出

**通过。** 2026-11-26，在同一具名项目里，摄影师给 `SET_PORTRAIT_01.jpg` 打了四星；客户在浏览器确认这一张，电脑同步后导出。软件正常退出后，新进程打开原项目和已保存的工作文件，无需重新勾选、重新确认或重新同步，再次导出了同一张。两份 JPEG 逐字节相同，全部解码 RGB 样本、方向和内嵌 ICC 也相同。[脱敏回执与摘要](RECEIPT.json)

两次输出都是 `SET_PORTRAIT_01_仿色.jpg`，各 281,095 字节，960 × 1440、RGB 8 位、方向 1。输出任务 ID 不同，侧车的源 JPEG 摘要、编辑版本和完整导出定义相同。逐字节比较 JPEG、解码出的 **4,147,200 个 RGB 通道样本**及 **3,144 字节 ICC**，零差异。输入网络 JPEG 本身没有嵌入 ICC；这里比较的是两次输出的 sRGB ICC。素材库资产、暗室目标和线上 ImageId 是不同标识：暗室导出侧车的库资产 ID 为空，本次依原项目、源路径与 SHA、编辑版本及锁定选片记录核对，未把不同模块的 ID 写成同一个。

实际 EXE 为 `2.3.0+05a9291f99f330f7159423616653f09189ccd47a`。App、选片服务、档期服务与 native-host 同源码构建，产品 `src` 树与刷新修复 `0adea8a7d77b8b5e1fa6823f798f9b40564d4022` 相同。[家庭联机记录](../home-tether-selection-20261123/REPORT.md)与 [f84 客户导出记录](../home-acceptance-20261122/native-final/REPORT.md)分别使用不同照片和项目，未拼接为本次通过。自动化工具的窗口定位超时均先核对实际状态，没有发现需要改动产品的可复现故障。

本轮仅验证 **一张落盘 JPEG、一个相册、一次独立重开**。未验证真实快门、手机、同名多照片或 RAW。原 f84 启动器摘要未变，原项目和其他选片服务未被用作测试根；测试结束仅停止本轮服务。原图、输出、工作文件、数据库、窗口快照和授权链接均留在公司机。
