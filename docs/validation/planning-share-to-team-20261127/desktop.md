# 光镜候选版：普通桌面入口验收

公司 Windows 上使用普通候选 EXE、原生项目仓库、独立候选服务和 WebView2 负责人窗口，使用三张获准 CC0 样片及合成策划数据。桌面驱动按启动时间、程序路径和 PID 只操作指定实例；截图只捕获该实例的窗口。测试间未停稳版服务或操作稳定应用窗口。

首轮实测 `KitaoPhotoSelector.dll` SHA-256：`593BAA071683814FEF793C6A83ECFC327F6FB590BD8C1B17A9F432217CA78D62`。此哈希只指代首轮桌面二进制。

| 验收 | 结果 |
| --- | --- |
| 正常入口首发 | 从策划中心打开两个同名测试项目中的指定项目，通过原生副标题编辑框输入「桌面光镜验收 · 初次发布」。点击标题栏「共享到团队」后，预检提示「文字 / 排版：两端对齐正文在线采用左对齐。」确认后打开已登录的负责人工作台，出现「项目成员」并读到刚输入的副标题。桌面入口变为「继续团队协作」。 |
| 关闭重开并续接 | 正常关闭并重新启动同一候选二进制，打开原项目，按钮直接显示「继续团队协作」。再次改写本地副标题，标题栏显示「本地有后续修改」。一键打开已发布的线上工作台，无发布确认；「当天时间表」显示成员保存的新值「北窗衣领复核 · 10:25」。桌面文件仍保留后续本地副标题，没被线上时间表改动回写；线上概览仍显示首发副标题。 |
| 保存失败保留原位置和草稿 | 在同名对照项目中只对该测试策划 JSON 持有只读句柄，阻拦原子替换。通过原生编辑器修改副标题再点共享，看到明确失败提示，编辑框仍保留当前值、线上窗口未开启、原文件哈希不变，恢复草稿已落盘。 |
| 重试和同名隔离 | 解除占用后，在同一个窗口和对照项目中重试；此前保留的副标题出现在该项目的线上工作台。两份同名策划各自持有不同的发布绑定。 |

使用 `tools/PlanningReview/accept-share-desktop.ps1` 复测。需要独立候选启动器生成的桌面实例回执和合成夹具的项目标识。脚本的 `-EditNativeBeforePublish`、`-ResumeOnly`、`-EditLocalDraft` 和 `-ExpectSaveFailure` 模式分别覆盖上表场景。公司截图和机器回执保留在候选交付 `_private/desktop-acceptance`，此仓库文档不包含邀请码、负责人临时票据或成员链接。此桌面验收不证明手机、公网或第二台物理电脑可达。
