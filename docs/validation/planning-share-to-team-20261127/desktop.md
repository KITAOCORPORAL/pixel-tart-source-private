# 光镜候选版：普通桌面入口验收

公司 Windows 上使用普通候选 EXE、原生项目仓库、独立候选服务和 WebView2 负责人窗口，使用三张获准 CC0 样片及合成策划数据。桌面驱动按启动时间、程序路径和 PID 只操作指定实例；截图只捕获该实例的窗口。测试间未停稳版服务或操作稳定应用窗口。

最终功能源码：`4900732c8ea643401bfaea41f5477142cd7bd874`。从干净源码构建最终候选，`KitaoPhotoSelector.dll` SHA-256 为 `8B576654E5F47C37149086FA765D1447A3C0D8C2FF3F8938B34B86D401DADB37`。首轮候选 DLL SHA-256 为 `593BAA071683814FEF793C6A83ECFC327F6FB590BD8C1B17A9F432217CA78D62`；两轮使用不同交付目录和隔离数据。

| 验收 | 结果 |
| --- | --- |
| 正常入口首发 | 首轮和最终候选均通过。从策划中心打开两个同名测试项目中的指定项目，通过原生副标题编辑框输入「桌面光镜验收 · 初次发布」。点击标题栏「共享到团队」，确认预检后打开已登录的负责人工作台。出现「项目成员」，读到刚输入的副标题，桌面入口变为「继续团队协作」。首轮可见预检提示「文字 / 排版：两端对齐正文在线采用左对齐。」 |
| 关闭重开并续接 | 首轮和最终候选均通过。正常关闭并重新启动同一候选二进制，打开原项目，按钮直接显示「继续团队协作」。再次改写本地副标题，标题栏显示「本地有后续修改」。一键打开已发布的线上工作台，无发布确认；「当天时间表」显示成员保存的新值「北窗衣领复核 · 10:25」。最终候选同时显示 B 的衣领图片区域批注。桌面文件仍保留后续本地副标题，没被线上时间表改动回写；线上概览仍显示首发副标题。 |
| 保存失败保留原位置和草稿 | 首轮和最终候选均通过。在同名对照项目中只对该测试策划 JSON 持有只读句柄，阻拦原子替换。通过原生编辑器修改副标题再点共享，看到明确失败提示，编辑框仍保留当前值、线上窗口未开启、原文件哈希不变，恢复草稿已落盘。 |
| 重试和同名隔离 | 首轮和最终候选均通过。解除占用后，在同一个窗口和对照项目中重试；此前保留的副标题出现在该项目的线上工作台。两份同名策划各自持有不同的发布绑定；最终候选发布对照项目后，初始项目的绑定文件哈希未变。 |
| 从空白策划到发布 | 最终候选通过。用桌面「新建策划」创建第三个独立项目；在实际富文本控件键入 `NORTH WINDOW - COLLAR TEXTURE`，在工具栏加粗并插入表格，保存的 RTF 包含加粗文字和表格。新建镜头，在系统文件选择器中选取获准的 `02_Autumn_fashion.jpg`，确认导入项目副本，再从参考图菜单选择「用于当前镜头」。原生策划与镜头文件引用同一个自有图片 ID。点击「共享到团队」后直接打开线上工作台，无预检问题、无额外确认。线上「文字」显示正文和表格单元格；镜头卡片提供「打开现场参考」。 |
| 候选服务停启后的重试 | 最终候选通过。只停止并重启独立候选服务。停机期间从桌面原项目点「继续团队协作」，看到明确可重试提示，绑定文件哈希不变，按钮仍可用。服务使用同一数据根和证书重启后，再点同一入口打开原负责人工作台，仍读到最新时间表、成员 B 的图片批注和负责人的已保存回复。验收结束时原项目的线上工作台保持打开。 |

最终候选重启时，整套脚本的首次页面轮询超时；在同一个窗口使用限定进程的 UI Automation 复核了时间表字段、线上概览和批注，并补拍了完成渲染后的截图。最终候选首发的部分瞬时截图不作为已登录或预检渲染证据；首发结果由当时的 UI Automation 控件和值确认。

使用 `tools/PlanningReview/accept-share-desktop.ps1` 复测。需要独立候选启动器生成的桌面实例回执和合成夹具的项目标识。脚本的 `-EditNativeBeforePublish`、`-ResumeOnly`、`-EditLocalDraft` 和 `-ExpectSaveFailure` 模式分别覆盖上表场景。公司截图和机器回执保留在候选交付 `_private/desktop-acceptance`，此仓库文档不包含邀请码、负责人临时票据或成员链接。此桌面验收不证明手机、公网或第二台物理电脑可达。
