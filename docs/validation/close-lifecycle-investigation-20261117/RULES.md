# 关闭与资源生命周期短规则（本调查已证实）

1. Dispatcher.Yield/排队不等于退出Closing：嵌套消息循环可执行回调。一个根窗口只由一处汇总关闭决定；组件不独立重发Close。
2. 取消或保存失败属于本次关闭的终止结果，不是稍后重试的许可。dirty文档、撤销历史和原文件必须保留；保存失败前后与不可逆释放故障分开。
3. 发出Cancel不等于任务结束。终止时禁止新工作/旧结果发布，向下传token，跟踪并等待子任务，再释放本作用域图像引用。
4. 暂时Unloaded与最终Dispose分开：前者可保留受预算缓存，后者完成后不得再次发布或重启工作。事件订阅和计时器必须有明确所有者。
5. 已保存、已冻结、已缓存不代表无主：保存revision、预览epoch、活动目标和资源租约各有身份；只释放自己拥有的引用，不清他人的导出/撤销输入。

依据：C1最终两进程加v1重复；C2/C3两轮；I1/I2两轮；I3最终及独立资源重复。逐项见REPORT、RUN_SUMMARY与receipts。第5条是已复现边界与既有prepared/共享输入合同共同约束；不声称本轮证实所有缓存都是泄漏。

这些规则仅写入本调查交付目录，供产品Codex审核纳入根规则。本轮没有更改根AGENTS或持久记忆。
