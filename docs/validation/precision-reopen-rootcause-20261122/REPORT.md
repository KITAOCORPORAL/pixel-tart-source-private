## 根因证据

第二次ushort大分配前设置明确边界，仅诊断运行暂停并采集Heap dump。采集前后GC计数均12/7/4，未观测到采集触发GC；但暂停/转储改变时序，整轮DIAGNOSTIC_ONLY，绝不作为资源PASS。dump及照片仅本机保存，SOS只读离线分析。

- 旧float数组482,236,440字节（约459.9MiB）在堆中仍存在，但gcroot为0；旧已Dispose生产VM gcroot也为0。宿主/闭包/async/事件/缓存没有在该捕获边界把它们强根保活；不是由WeakReference.IsAlive推出结论。不能外推所有时刻/路径无持有错误。
- SOS live对象8.31MiB；不可达对象（不含Free）537.39MiB；Free块271.53MiB。GC当前提交821.98MiB，其中LOH784.22MiB。最大Free块125.60MiB，小于新ushort所需229.95MiB。死数组尚未变成可复用空洞，空洞也不能拼成连续数组。
- Private约1682.34MiB减当前GC提交后，非GC私有差额上界860.36MiB；包含运行时/堆/栈等，不能全部归给WIC。31个去重WIC压力对象合计框架报告236.24MiB，属于估算，不是实际私有提交普查。精确原生归属未编造。
- 第二次原路径还要完整ushort约229.95MiB、再完整float约459.90MiB；在上述死对象/提交/原生资源之上形成峰值。原STOP约2378MiB是容量失败，不能称已经证明泄漏。当前挂起任务链是新Decode/LoadSession，不是旧VM在途渲染；SOS记录见diagnostic。

## 最小产品修复与宿主修正分开

只在现有HighBitDepthImageBuffer内增加独占、规范方向的RGB48 backing，不新增全局Session/资源框架或弱缓存。解码数组仍复制为独占源，不能借用可变外部数组；准入点显示/导出/小代理按原`ushort/65535f`逐条带转换。master由459.90MiB float改为229.95MiB精确RGB48，没有新量化。旧`Rgb32`接口在明确调用时一次性兼容展开、释放其内部RGB48引用；已有空间/图/整帧API保留数学与容量边界。

没有改节点公式/顺序、旧配方、方向语义、TIFF量化/ICC、发行解码器。没有销毁共享master，没有全局cache清理、强制GC、LOH压缩、裁工作集或改预算。

宿主描述/逻辑float哈希改为不触发新表示整帧展开的读取；这是观察器适配，不包装成旧失败根因。释放改为等待已识别本作用域Task实际结束并Dispatcher idle，10秒失败上限，去掉原1秒关闭延时。原700ms UI settling保留且没有为等GC延长或按内存下降循环；最终门禁无诊断暂停/转储/分析器。
