# 工作台 API 验证　2026-11-27

在公司 Windows 机用新的数据目录和回环 HTTPS 端口，依次启动传统审稿服务、工作台、新恢复实例。每个临时服务仅由创建它的测试进程关闭。以下回执记录实际 HTTP、持久化和导出验证；不包含成员码、私有路径、证书、源照片、数据库或 dump。每份 JSON 与该次本地测试输出逐字节一致。

| 回执 | 已验证结果 |
|---|---|
| [导入、操作与恢复](BACKEND-API.json) | 未启用工作台时 `/api/state` 保持 v1 形态；旧版先独立导出，工作台从该副本导入。Basic 可写但不能发批注，Pro 可批注。段首插字后选区随原字平移，旧版本产生冲突；同一操作重送未重复。新增、重排、归档、恢复表页后 `section` 和行单元格保留。画布平移保留原图区域，移除对象后原讨论标记位置失效。团队成员能取回与导入完全相同的图片字节；移除后再取状态和图片均为 403。重启保留内容；导出再导入仍能打开图片和讨论，原成员不重新获权。导入源目录最初 8 个文件的 SHA-256 逐项复核无变化；新恢复包的 3 个文件为原生策划 JSON、分镜 JSON 和已拥有的参考图。 |
| [分镜与原生正文](BACKEND-SHOTS.json) | 单次编辑同时改分镜名称与拍摄要求；旧入口先改名后，过期的工作台修改进入冲突。分镜能移到第一位。无旧 WPF 富文档包时，导出副本的原生 Body 包含实际简报段落纯文字。已有原生富文档包的原稿保留，工作台编辑另存扩展。 |
| [Word 审阅稿](BACKEND-DOCX.json) | 打开新工作台的负责人下载路由获取真实 DOCX；旧实例未映射（404），未认证 401、普通成员 403。样例 ZIP 的 OOXML 检查和独立 python-docx 读取均成功：两张 Word 表、六镜顺序、选区加粗/斜体/下划线/字号/颜色和图片图注。生成没有改变文档 revision，也未输出评论、身份、原图或邀请信息。 |
| [字体与分镜图注位置](BACKEND-TYPOGRAPHY-ANCHORS.json) | 正文图注段落、受限字体族、字距和行距写入并生成相应 Word 属性。三组非法值被拒绝。分镜图片批注使用 pageId、shotId、assetId、实际 SHA 与归一化原图区域；换成不同摘要的副本后原批注保留原 hash/rect 并标失效，换图后才传到的旧批注也标失效。错误摘要与不存在的素材被拒绝。 |

工作台源码基线 `a398d6c264b4a90b6e6ab01a0cf453f8e5945312`；上述验证基于本轮分阶段改动的实际 Release 输出，完整工作台交付版本以总回执标注的提交/载荷为准。恢复导出是新的独立原生目录；凭据与邀请不会随之移植。单机 WPF 并未实现编辑 `PixelTartWorkbenchV1` 中的新页，与其扩展兼容性不要混作正式 UI 验收。

DOCX 包含可编辑正文、基本格式、表格、分镜及参考图标题；自由画布几何、实际图片、复杂 WPS 版式及讨论不导出。工作台纸面效果须另作打印或视觉验收。本次未验证 Word/WPS 的逐页打印外观。回环 HTTP 功能验证不能代替实体第二台机器的局域网访问、真实输入设备或最终桌面 UI。

[原生资源投影回执](BACKEND-NATIVE-PROJECTION.json)：用真实 v1 原生存储器导出的隔离测试项目副本补入可辨识的测试字段（非客户项目），在另一空根执行导入。15 个基本栏目均来自该副本；如有灯具另生成灯具清单。实测设备与道具、归档标记、设备来源 ID、关联镜头、灯具、时间表、文件显示名、受管图片和原简报内容，源目录 SHA 逐文件不变。重新导入新导出物仍使用原工作台页 ID；新建空实例依然仅有三张初始页。原生富文档包只核对不透明内容保留，未宣称解析旧 WPF 富文本、重绘历史画布快照或读取外部附件。时间安排、资源表是工作台初始投影，编辑后依靠扩展恢复，不反向改写全部原生源表；原生完整语义保存在隔离副本中。过大页面按工作台原有限制停止，不截断原数据制造成功。
