# 高光三方案 · 可审核设计，未实现

本轮目标是摄影调色中亮部过渡与结果稳定性，不以“更少贴顶像素”替代肤色、材质、立体感和可预测操作。产品生命周期方案B的批准与本表HL-A/HL-B/HL-C无关。MaxChannelShoulderV1数学、Knee=.75、默认曝光与旧配方均未改。

## 现有材料给出的摄影判断

- 肩部EV0：高亮平均线性Y由0.729945降至0.650126（−10.93%），相对局部梯度RMS约−10.44%；亮斑边缘较柔，同时皮肤亮感与体积感更平/更灰。原输入已有64971个贴顶通道，变为非贴顶不证明旧细节恢复。
- 发丝/皮肤亮边EV0：高亮Y约−11.62%，相对梯度约−11.20%。共同RGB缩放在非负线性域保持比例，但不等于感知肤色或立体感无损。
- 暖纹理EV+1：原高亮Y≈0.89086，候选同曝光≈0.69174，中间调匹配后≈0.69585。后两者仍明显更暗。相对梯度可比大量新贴顶的原图更高，说明收益不只是全图曝光更低；也不能忽略22%左右的高亮亮度代价。此处是暖受光背景，不是白衣或金属。
- 合成中性亮纹理EV0：相对梯度约−39.46%，可反证“斜率不为零=局部反差无损”；它不是白衣实拍。
- Canon夕阳固定ROI缺足够中间调锚点，三种EV的匹配列均不可用。仅同曝光的夕阳渐变不足以判断同亮度观感或多光源稳定性。

**结论：A值得继续优先设计，但固定V1的收益尚不足以形成默认推荐或产品接纳。** 现有材料支持“避免曝光新增的部分裁切并改变亮部形状”，不支持“恢复旧数据”“稳定改善所有人像/反光材质”。是否值得约10%亮部亮度/局部反差损失，仍需用户在固定对比中选择，以及与既有工具的公平对照。

## 三方案比较

|方案|用户语义与正确性|二阶/三阶影响|迁移/长期成本|建议|
|---|---|---|---|---|
|HL-A 保持曝光行为，独立高光压缩工具|EV继续表示原曝光；压缩有单独开关/状态。只有启用时在曝光gain后、原clip前处理；关闭完整走旧路径|能明确表达曝光与高光取舍，但多一个控制；必须防双重肩部、顺序歧义和误当恢复工具；对发丝/白衣/金属可能压平|新明确工具/载体版本、缓存key与能力检查，不改变旧配方；有显示线性接口适配成本，不是随意在末端加节点|优先评审，先固定域/顺序与区别于现有工具的收益；当前不实现|
|HL-B 显式版本化曝光模式|LegacyClip为默认，另选Shoulder模式；用户应知道开启后EV0也改亮部|面板少一个工具，但同一EV与旧曝光亮部含义分裂，版本切换可显著改变白点和亮感；诊断/教学成本高|新模式必须显式写入配方/Decode或Render key，保存/导出统一；旧文件不得暗迁，缺字段等于LegacyClip|技术可行备选；不能用更改Version1默认值快速接入|
|HL-C 更上游保留数据/色调映射|针对LibRaw:uint16、WB/矩阵与工作域/输出映射等更早损失；有机会保留后续原本不可用的信号|会影响解码、色域、曝光、噪声、颜色、显示与导出；输入域改变不能复用已显影TIFF的数值结论|需新输入合同、原生/配方版本、缓存、真实RAW数值对照和跨相机/ICC回归；风险最高|当前不启动。先确定上游确实存在且能合法取得的信号，不能仅因已有TIFF贴顶就宣称有可恢复RAW细节|

三方案都不能重建传感器饱和或已丢弃/量化的值。HL-C也只有“保留尚未丢失数据”的可能，不是已证明的恢复能力。本轮没有调候选、实现新模式或运行新的RAW批次。

## 优先方案A：最强反对意见

1. **是否只是把高光压暗？** EV0白点1→0.875，亮度损失是数学必然。中间调匹配只对固定0.03≤Y≤0.35输入锚点，没有把白点也匹配。现有+1纹理显示新增裁切减少，但仍不能排除现有曝光/曲线在匹配白点后也能达到同样观感。未做的新公平对照必须明确NOT_RUN，不自行重渲染补齐。
2. **皮肤、白衣、反光立体感？** 皮肤已看到压平代价；白衣/金属材料缺失，不能从合成纹理外推。在低Amount或不同Knee下是否更好本轮没有证据，也不自动调参数找答案。
3. **与高光/白色色阶/曲线重复？** BasicTone已有亮度肩部和高光/whites的加权Bend，Levels/Curve也能降白点。A的候选差别是最大通道共同缩放与clip前位置，而不是“第一次有高光控制”。必须在相同中间调、相近白点和统一查看比例下，证明操作可预测/色形或纹理优势；否则新增面板不值得维护成本。
4. **开关/强度/顺序理解成本？** 用户同时见Exposure、Highlights、Whites、Curve和Highlight compression，容易叠加两次压缩。最小设计先只面向已显影曝光这一路，顺序固定且可见，不允许拖到已clip之后还宣称preclip收益。直方图/白点反馈应显示压缩在做什么。Amount中间值的数学和感知标度尚未决定。
5. **亮色/色域外边界？** 最大通道膝点依颜色分量触发，不是恒定Y阈值；高饱和色可在较低Y开始压缩。非负线性RGB比例保持不等于编码HSV、绝对色度、不同适应状态下感知色相不变。负值输入当前V1不支持，不能先clamp为0再宣称保留数据。
6. **局部反差与数值平台？** 连续斜率仅在已测试有限区间成立，强高亮/极大值仍可能因浮点或输出量化平台。压缩不可避免减少某些增量。不能用“零贴顶通道”替代对亮度梯度和材质的评价。
7. **独立UI能否真的不改曝光语义？** 若原API已经返回clip后的RGB，在其后新增A只能压暗平台。A需要新、显式、版本化的preclip适配点；关闭和旧配方必须完整保留原函数。这个成本不能隐藏成“只加一个按钮”。

反驳之后仍优先A，是因为用户能将EV与风格压缩分开作决定，风险比替换默认曝光或改上游RAW更小；这只是一项有条件设计推荐，尚未证明摄影收益足以接入。

## A的域与处理顺序合同草案

### 接受范围

- 首阶段仅 RenderedSrgbD65：已经正确解释/转换成sRGB原色、D65白点的编码RGB，非sensor-linear、非任意ICC/ProPhoto/ACES。原图若是P3/AdobeRGB/ProPhoto，必须由独立已验证色彩管理路径转换并留下身份；不能只改标签。
- 计算域是相对显示线性sRGB浮点；EOTF后乘既有2^EV得到非负值，允许>1。线性膝点m=.75，约等于中性sRGB编码.880825，不是编码.75。
- 现有候选ApplyRendered严格[0,1]有限；ApplyLinear接受有限非负值，EV限定[-5,5]且乘法不得溢出。NaN/Inf/负值拒绝，不能静默裁切或换公式。更宽色域转换产生的负值是新域问题，先拒绝/显式报告，不能声称当前V1支持。
- 沿用原alpha/尺寸/方向策略，候选只作用于RGB；不从预乘alpha或显示器像素取色。存在透明/额外通道时需明确unpremultiply/复合合同，当前没有验收。

### 顺序与双曝光防护

拟议链：已解释的编码sRGB → 同一EOTF → 既有EV gain → **A（新版本、原clip之前）** → 原OETF → 原最终clip/量化/ICC编码。现有候选自带ExposureEv；若未来在gain后复用ApplyLinear，候选内部ExposureEv必须固定0，绝不再乘一次gain。此适配点尚未实现。

原曝光、BasicTone、ProfessionalRaw.Display不是同一路。A不直接插在BasicTone.EncodeGamut或RAW的中性轴映射之后来宣称同等preclip收益；也不同时修改这些公式。若将来需对整图多节点链提供A，必须另列版本/顺序与新证据。

### 关闭和Amount=0

关闭或Amount=0：配方判定后直接走原LegacyClip全路径；不得“跑完候选再混回”、不得EOTF/OETF往返后才当零值、不改浮点舍入/像素，旧配方的序列化语义与缓存定义保持。新配方若显式含新工具元数据，文件字节/缓存hash可以不同，但不能以此掩盖像素差异；新格式的旧reader行为需明确拒绝。要求旧输入/旧配方逐样本位一致及预览/保存重开/导出一致。对象引用可依现有所有权策略复用或复制，但像素字节必须相同，不能为旁路破坏共享master。

Amount>0若保留中间强度，混合发生在哪个域、对单调性/比例/斜率的影响和可见刻度必须先定义并独立数值比较；本轮不选插值公式、不模拟中间Amount。现有V1没有Amount控制，所以“零强度恒等”目前是新设计的验收要求，不是现成能力。

## 长期退出条件与缺项

若与既有工具在公平匹配下没有清楚收益，或皮肤/白衣/金属的体积感代价不可接受，则停止A接入，不以更多自动调参追赶。继续所需材料/矩阵见MATERIAL_GAPS.md。进入实现前仍须本仓像素门禁、两份固定成熟实现具体入口/许可、真实输入profile验证、版本化及同定义预览/重开/导出合同；已有标量对照不等于完整应用/相机校准。
