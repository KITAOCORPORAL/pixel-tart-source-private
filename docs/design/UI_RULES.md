# Pixel Tart UI Rules v1.0

以下规则是未来所有页面开发的硬约束。

## 1. 不要为了展示更多信息牺牲图片

图片相关页面先确定 Gallery / Viewer / Canvas 面积，再安放信息。空间不足时收起 Inspector、Navigation 和高级工具，不先缩图、缩字或增加滚动层。

## 2. 不要把所有东西做成 Card

Card 只表示可独立选择、移动或进入的对象。普通章节用留白、对齐和标题；禁止 Card 套 Card、统计卡墙和用 Border 包住每段文字。

## 3. 不要把所有功能放一级菜单

稳定导航只放高频工作空间。对象动作不占一级导航，系统设置不与摄影工作争夺同等视觉权重。

## 4. 低频功能进入右键、菜单、命令

右键服务当前对象，菜单服务跨对象命令，命令服务键盘效率。不可见不等于不可发现：通过 Tooltip、快捷键提示、首次上下文提示和命令搜索建立可发现性。

## 5. 图片相关页面必须视觉优先

素材库默认 Thumbnail，灵感托盘必须有图，情绪板必须是画布，策划中心必须持续显示视觉参考，项目必须有封面/代表图片，日历必须连接拍摄故事。

## 6. 一个视域一个 Primary

页面、Dialog、Drawer 各自最多一个实心 Accent 主操作。多个“主要”按钮说明流程尚未分清。

## 7. 界面使用语义 Token

禁止页面级 Hex、任意字号、任意间距和局部主题。所有颜色、字体、空间、圆角、动效从 v1.0 Token 获取。

## 8. 4px 是空间语法

合法视觉间距为 4、8、12、16、24、32、48 DIP。禁止靠 3、5、6、7、9、10 等碎片值“调到差不多”。

## 9. Inspector 只解释当前选择

不把筛选器、批处理、诊断、设置和未来功能永久塞进 Inspector。无选择时收起；复杂编辑进入 Drawer 或专门工作区。

## 10. 不展示未实现能力

未来功能写在规范与 Roadmap，不以大量禁用按钮、空 Tab 或“即将推出”占据生产界面。

## 11. 状态必须诚实

Loading、Empty、Offline、Partial、Error、Success 清楚区分。错误说明源文件安全与恢复路径；成功只在真实完成后出现。

## 12. 源文件安全必须说人话

准确区分移除引用、移出集合、移动到回收站和永久删除。任何可能改变磁盘文件的动作都必须说明范围与恢复方式。

## 13. 图片上不堆 UI

默认只显示图片；Hover 最多出现当前任务必需的 1–3 个动作；选择轮廓绘制在图片外；路径、标签堆和分析信息进入 Inspector。

## 14. 动效只解释变化

允许 Fade、Smooth Transition、Progressive Loading；禁止弹跳、大幅缩放、发光和游戏化庆祝。尊重 Reduced Motion。

## 15. DPI 不是测试尾项

页面从设计开始考虑 1080p、2K、4K 与 125%、150%、200% Windows DPI。不得用固定像素、缩小文字或裁字换取布局通过。

## 16. Keyboard 是组件状态

每个交互组件必须定义 Tab、Enter、Esc、方向键、Context Menu 与焦点返回。纯图标按钮必须有 Tooltip 和可访问名称。

## 17. 页面不能创造组件分支

新需求先组合公共组件。确需新增变体时，在 Design System 中完成全状态、主题、DPI 与键盘契约，再供页面使用。

## 18. 参考工作方式，不复制产品皮肤

Lightroom、Capture One、Eagle、Milanote、摄影画册和数字档案是研究对象，不是临摹模板。Pixel Tart 使用自己的摄影工作流语言与唯一 Accent。

## 19. 评审先看真实运行画面

XAML、Token 和测试只是实现证据。最终必须查看真实内容、空状态、加载、错误、高 DPI 和键盘焦点截图。

## 20. 冲突裁决

发生冲突时按以下顺序决策：源文件安全 → 可访问性与可恢复性 → 图片观看 → 当前任务效率 → 信息完整 → 装饰。不能以“页面特殊”为理由绕过前四项。
