# 设计交接与验收约定

## 1. 交付定位

本包是全产品源码审计与设计基线，状态PARTIAL，不是最终视觉设计、不是产品实现、不是桌面验收。完整范围已经登记；动态入口语义仍有待复核项，必须查看EntryConfidence / SemanticReview / ScopeNote。不要把“字段齐全”误当“行为全部确定”。

## 2. 文件阅读顺序

1. PRODUCT_MASTER_SPEC：范围与硬约束。
2. INFORMATION_ARCHITECTURE：真实十项导航、对象与入口关系。
3. CORE_USER_FLOWS：13条完整任务路径。
4. CROSS_PLATFORM_AND_SYNC：所有跨端状态与冲突目标。
5. DESIGN_SYSTEM_REQUIREMENTS：统一视觉、输入、焦点与DPI。
6. FEATURE_INVENTORY → PAGE_AND_STATE_MATRIX → ACTION_INVENTORY：逐项追踪。
7. IMPLEMENTATION_STATUS_AND_GAPS + SOURCE_AUDIT + ENTRY_COVERAGE：证据与未决。

GROK_FULL_PRODUCT_MASTER.md整合上述全文、三份CSV全文及JSON证据；内容大，不删减为几个示例。若模型上下文不足，按整合版章节边界分批读取，不把未读章节当完成。

## 3. ID稳定性

FeatureID采用F-域-序号；本版242项范围+13项待归属桶。PageID采用P-稳定路由/表面名；旁支P-BRANCH-*与产品表面分离。ActionID采用源路径+入口类型+符号+参数/标签+同签名序号的稳定摘要；数据驱动参数用A-CLR-PARAM-类型-key，目标动作用A-REQ-*。

交付后将本版ID视为注册表：改文案、搬文件、改路由不得自动重新生成ID；保留旧ID并记录别名/迁移。当前摘要生成用于首次注册，不承诺对源码重命名自动稳定。废弃ID保留，不复用。重复入口（菜单/快捷键/按钮）可有不同ActionID，但必须共享业务意图，不计成三份实现。

状态稿ID为PageID::state。设计工具画板命名：PageID / state / viewport / density / language；动作注释带ActionID与FeatureID。每项功能至少有入口或明确目标动作；后台操作可映射状态图而不是新按钮。

## 4. 设计稿必备

每页：布局优先级、主/次操作、工具栏/侧栏/底栏、全部菜单和弹窗、返回焦点、初始/正常/空白/加载/失败/离线/冲突/批量/只读/禁用的适用说明。只读组件继承宿主，不能为凑数画独立页面。

每动作：名称、位置、目的、前提、输入、触发行为、成功/失败反馈、禁用原因、取消/重试/撤销、跨端影响、快捷键、确认、源证据与实现状态。ACTION中设计反馈与实际反馈严格分列；未语义核对的行先补审，不用通用模板直接开发。

每危险操作：对象范围、影响文件、不可逆性、确认方式、撤销/恢复能力。项目只归档恢复。输出不覆盖源。客户公开发布/权限配对须确认可见范围。复制诊断不得包含密钥。

## 5. 交接分期（建议，不是已批准开发排期）

- D0：收口导航数量/命名与品牌迁移；本次保留源码十项。
- D1：归片、素材库、Color Studio、即时胶片的核心与错误状态；精确处理输入身份和输出恢复。
- D2：策划/自由画布/联机/客户选片/收支；完整菜单与局部状态。
- D3：档期三端网络、身份、离线、时区与冲突；扩展/手机目标。
- D4：完整文字处理、专业HDR/ICC、厂商相机适配等能力路线。

## 6. 验收矩阵

|层级|本次|后续门槛|

|源码入口索引|执行词法扫描+重点语义复核|清除未解析DataContext/事件/工厂|
|设计覆盖|全部范围登记；状态稿未绘制|每个Action有明确最终行为与对应画板|
|产品单元/契约测试|本次未运行|按精确分支SHA运行，不借旧报告通过|
|桌面原生交互|NOT_RUN|真实点击/键盘/拖拽/关闭恢复/不同DPI|
|照片质量/色彩|NOT_RUN|授权真实RAW/JPEG、预览导出一致性、独立质量基准|
|联机设备|NOT_RUN|真实支持设备、断连/恢复与能力矩阵|
|三端同步|未实现端到端|真实桌面+手机+Web、乱序/重复/离线/冲突|

不能以截图/自动渲染/公开方法/测试通过替代用户入口、真实操作和物理DPI验收。历史BLOCKED不改为PASS。
