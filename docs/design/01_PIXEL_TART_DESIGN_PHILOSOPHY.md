# Pixel Tart Design Philosophy v1.0

状态：Normative（规范性）

适用范围：Pixel Tart 全部桌面页面、模块、浮层与未来扩展

产品隐喻：摄影师的数字暗房

## 1. 产品体验命题

Pixel Tart 不是 ERP、企业后台、数据管理系统、AI 工具面板或普通素材管理器。它是摄影师观看、挑选、组织、策划、拍摄与交付作品的私人工作空间。

用户打开软件时应感到“我进入了自己的摄影工作空间”，而不是“我正在管理文件”。界面的空间语言来自摄影工作室、编辑桌、暗房、个人影像档案馆和数字画廊；数据只服务于摄影决定，不成为视觉主体。

## 2. Image First

全产品遵循唯一优先级：

> 图片 > 空间 > 信息 > 控件

- 图片是工作对象，不是装饰背景或卡片封面。
- 空间用于观看、比较、停顿和判断，不用于塞满功能。
- 信息只在能帮助当前摄影决定时出现。
- 控件在需要时出现，并在任务完成后退回背景。
- 没有图片的页面，也必须以“下一项摄影工作”而非统计数据为主角。

当图片面积与附加信息冲突时，默认保留图片；当画布与固定面板冲突时，默认让画布获得剩余空间；当常驻按钮与上下文操作冲突时，默认使用上下文操作。

## 3. 界面应该退后

Pixel Tart 的 Chrome（导航、工具栏、Inspector、状态栏、浮层）必须安静：

- 使用中性、低偏色背景，避免干扰照片色彩判断；
- 同一视域最多一个 Primary Action；
- 依靠留白、对齐与文字层级组织内容，边框最后使用；
- 低频能力进入右键、菜单或命令，不永久占用画布；
- 无当前选择时 Inspector 收起或仅显示一句轻提示；
- 状态色不得大面积覆盖照片；
- 未实现能力不得以一排禁用按钮假装存在。

照片应该成为主角，界面只提供可靠的工作台面。

## 4. 五个体验品质

### 4.1 Calm / 安静

没有发光、弹跳、彩色按钮墙和无意义的动画。Hover 可被感知，但不会抢走视线。

### 4.2 Tactile / 有触感

缩略图像接触印相，灵感托盘像桌上一叠照片，情绪板像工作室墙面。触感来自比例、层次、拖放反馈和克制阴影，不来自拟物纹理。

### 4.3 Precise / 精确

比例、裁切、像素、色彩空间、文件状态和操作影响范围必须准确。专业感来自可靠，而非复杂。

### 4.4 Personal / 私人

空间围绕用户的项目与作品组织；不使用销售漏斗、企业指标或运营话术。允许工作区保留个人节奏，但不允许各模块创造自己的视觉语言。

### 4.5 Honest / 诚实

Loading、Empty、Offline、Partial、Error、Success 清楚区分。界面不伪造数据、不掩盖源文件风险、不用“AI”装饰普通能力。

## 5. 摄影工作流语言

Pixel Tart 不复制 Lightroom、Capture One、Eagle 或 Milanote 的皮肤与布局，只吸收被验证的工作方式：

- 从 Lightroom 学习让照片与故事成为入口，并减少不必要的编辑阻力；
- 从 Capture One 学习色彩中立、快速预览、片场可靠性和可收拢工作区；
- 从 Eagle 学习视觉资产的快速浏览、分类、标签与找回；
- 从 Milanote 学习自由画布、墙面式创作和图像与笔记的空间关系；
- 从摄影画册学习节奏、留白、序列与跨页关系；
- 从美术馆数字档案学习准确 Metadata、克制导航和尊重原作。

形成 Pixel Tart 自己的语言：`观看 → 选择 → 聚集 → 编排 → 拍摄 → 交付 → 归档`。

## 6. 设计决策顺序

每次新增或评审页面，依次回答：

1. 用户此刻要看哪张照片、哪组照片或哪个摄影故事？
2. 为了做决定，照片需要多少空间？
3. 哪些信息此刻不可缺少？
4. 哪个操作是当前唯一主操作？
5. 哪些能力可以延迟到选择、Hover、右键、菜单或命令？
6. Loading、Empty、Error、Keyboard 和高 DPI 是否完整？

若无法回答第 1 项，页面尚未形成 Pixel Tart 的体验命题。

## 7. 规范治理

本目录中以下文件共同构成 Pixel Tart UI Design System v1.0。新页面必须使用语义 Token 和正式组件，不得从旧页面复制局部色值或页面内 Style。历史设计文档可作为背景材料；发生冲突时，以本套全大写编号文件、`UI_RULES.md` 和 `CURRENT_UI_AUDIT.md` 中的规范性结论为准。

规范变更必须说明：用户问题、受影响页面、Token/组件变化、DPI 与可访问性影响、迁移与回滚方式。不得用单页例外悄悄改变全局语言。

## 8. 成功标准

- 隐藏所有文字后，用户仍能从图片与空间判断页面用途；
- 隐藏所有照片后，界面不会退化为彩色 Dashboard；
- 连续使用数小时，颜色、字号与动效不过度刺激；
- 同一动作在不同页面拥有相同外观、状态与键盘行为；
- 用户能够确信源文件是否会被改变，并能从错误中恢复；
- 任何新增功能都不能以牺牲图片为默认代价。
