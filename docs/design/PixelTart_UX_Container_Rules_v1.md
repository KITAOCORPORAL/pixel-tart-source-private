# Pixel Tart UX Container Rules v1.0

## 1. 容器选择原则

容器由任务持续时间、上下文依赖和用户是否需要对照主工作区决定，而不是由实现便利决定。

| 容器 | 使用场景 | 禁止场景 |
| --- | --- | --- |
| Page | 长期工作、连续浏览、需要完整历史或大量内容 | 一次性确认、小型配置 |
| Modal | 短时、单目标、完成后返回原上下文 | 长列表、长期编辑、多层嵌套 |
| Drawer | 快速查看或编辑，必须保留主页面上下文 | 完整四步规划、大量表格 |
| Tooltip | 非关键解释、快捷键、术语说明 | 承载必须阅读的规则或主要操作 |
| ContextMenu | 与当前对象直接相关的次级动作 | 页面导航、完整表单、说明文字 |

## 2. Page

长页面使用可用宽度，不把 2560 或 2976 宽窗口压成居中的窄列。页面只保留一个主滚动区；局部滚动不得超过两层。工具栏、筛选、内容和状态栏必须有明确顺序。

## 3. Modal

短工具宽度 760–960 DIP；中型设置 960–1200 DIP；完整拍摄规划上限约 1000 DIP。Modal 包含固定 Header、可滚动 Body 和固定 Footer。标题说明任务，Footer 右侧最多一个 Primary。

Modal 关闭时应恢复触发控件焦点；Esc 关闭非破坏性弹窗；存在未保存更改时必须确认。不得再套第二个业务 Modal。

## 4. Drawer

Drawer 用于日期概览、排期快速编辑、照片检查器和局部详情。默认从右侧进入，宽度随内容选择 360、420、480 DIP，圆角 10。Header 和 Footer 固定，Body 独立滚动。

Drawer 不得遮住触发对象的关键上下文；小窗口下可以覆盖内容，但必须有明确关闭按钮和 Esc 行为。

## 5. Tooltip

Tooltip 延迟出现，不抢焦点，不含按钮。文字应在 1–3 行内说明“这是什么”或“为什么不可用”。安全规则、错误恢复和文件删除说明必须进入页面或 Modal，不得只放 Tooltip。

## 6. ContextMenu

菜单只包含当前对象动作，按查看、编辑、状态、归档或危险动作分组。危险动作置底并使用 Danger 文本。菜单项使用动词，不使用模糊的“更多设置”。

## 7. 滚动和焦点

每个容器必须声明主滚动区。Header、摘要和 Footer 不随任务列表滚动。导航完成后将焦点移到页面标题、Drawer 标题或 Modal 第一个有效输入。键盘焦点必须可见。

## 8. 响应式规则

1280×720 仍必须保留主要操作和关键内容。优先压缩空白、折叠次要区、将右侧面板改为 Drawer；禁止缩小正文。所有容器必须在 100%、125%、150%、175%、200% DPI 下验证。
