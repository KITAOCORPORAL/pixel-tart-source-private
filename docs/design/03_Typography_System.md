# Pixel Tart Typography System

状态：Design Constitution v1.0  
目标：建立具有摄影标题感、信息清晰且适合长时间观看的六级文字系统。

---

## 01 字体气质

Pixel Tart 的文字应像摄影书的目录、暗房标签和档案注释：安静、清楚、不过度表演。字体服务于照片与判断，不制造游戏、科技或未来感。

禁止使用：

- 游戏字体、像素字体、机械科技字体；
- 过度窄体、过度几何或持续全大写的正文；
- 依赖花体营造“艺术感”；
- 多种字体混用表达模块差异；
- 用缩小字号解决布局不足。

---

## 02 字体家族

### 2.1 默认 UI

```text
中文：Microsoft YaHei UI
拉丁、数字：Segoe UI Variable, Segoe UI
回退：系统无衬线字体
```

默认界面不引入网络字体，保证 Windows 离线、高 DPI、安装包和回退环境一致。

### 2.2 摄影标题感

摄影标题感来自留白、比例、字重、行宽与文案，而不是另加一套装饰字体。项目名、拍摄故事名和作品集标题仍使用默认字体，可通过更大字号、较松空间和较少辅助控件建立编辑感。

文件名、EXIF、路径、快门、光圈、焦距、金额与时间使用 `LatinNumericFontFamily`，确保数字对齐与辨认。代码式等宽字体只用于确有技术意义的哈希、诊断 ID 或不可解析原始值，不进入普通页面。

## 03 Typography Scale

所有字号单位为 DIP。新界面只允许以下六个语义层级：

| 角色 | Token | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| Display | `Type.Display` | 28 / 36 | SemiBold | 沉浸 Preview 标题、工作台当前故事；每页至多一个 |
| Heading | `Type.Heading` | 22 / 30 | SemiBold | Page、Dialog、Drawer 主标题 |
| Section | `Type.Section` | 16 / 24 | SemiBold | 页面区块、Inspector 主要分组 |
| Body | `Type.Body` | 13 / 20 | Regular | 正文、表单、按钮、菜单 |
| Caption | `Type.Caption` | 12 / 18 | Regular | 说明、时间、次级状态、帮助文本 |
| Metadata | `Type.Metadata` | 11 / 16 | Regular / Medium | 文件名辅助信息、EXIF、尺寸、序号 |

辅助数字可使用 `Type.Numeric`：24 / 30 SemiBold，但仅在数字直接支持下一步判断时使用；它不是 Dashboard 指标卡许可证。

### 3.1 迁移映射

| 旧角色 | 新角色 |
| --- | --- |
| PageTitle | Heading |
| Hero | Display 或 Heading，按语义选择 |
| Card | Section 或 Body Medium |
| Secondary | Caption |
| NumericLarge | Numeric |
| 9、10 DIP 局部小字 | Metadata，最小 11 DIP |

---

## 04 层级规则

- 一个 Page 只有一个 Heading；同级区块都使用 Section。
- Card 不拥有独立“卡片标题字号”；标题角色由内容层级决定。
- Button、Menu、Input 默认使用 Body，紧凑工具栏可使用 Caption，但不得低于 12 DIP。
- Metadata 只承载可略读信息，不承载删除影响、错误恢复、付款结果或主要操作。
- 强调优先使用位置和字重，不优先使用 Accent 颜色。
- 同一文本不同时使用“大字号 + 高饱和色 + 全大写 + 粗体”。
- 连续两级标题之间至少有 4 DIP 的视觉差异或明确的字重差异。

## 05 摄影内容排版

### 5.1 项目与照片标题

- 项目名允许 1—2 行，优先完整显示，不与状态 Badge 争抢同一行。
- 照片文件名默认单行，宽度不足时中间或尾部截断；悬停或 Inspector 可显示完整值。
- 拍摄故事标题可以使用 Display，但旁边只保留时间、地点等最必要 Metadata。
- 不把扩展名、路径、尺寸、评分全部堆进缩略图标题行。

### 5.2 Metadata

建议次序：文件名 → 拍摄时间 → 尺寸 / 格式 → 评分 / 标记。按当前任务删除不相关信息。

- EXIF 数字保持不换行；单位与数字之间规则统一。
- 日期默认使用本地易读格式；密集表格可以使用 `yyyy-MM-dd`。
- 时间使用 24 小时制；跨日必须显示日期。
- 金额使用等宽数字并明确货币；隐藏金额时不保留模糊色块。
- 路径只在定位、冲突或错误恢复场景显示。

## 06 文案与微文案

### 6.1 语气

清楚、具体、平静。使用摄影师能理解的动作词，避免系统术语、营销语和拟人化 AI 文案。

推荐：

- “导入照片”而非“启动资产摄取流程”；
- “加入灵感托盘”而非“添加到容器”；
- “3 张照片未能复制”而非“任务执行异常”；
- “选择一个文件夹开始浏览”而非“暂无数据”。

### 6.2 状态句式

- Loading：正在发生什么，可否继续其他工作。
- Empty：当前情况 + 下一步。
- Error：原因 + 影响 + 解决方式。
- Success：完成了什么 + 必要时提供撤销。

禁用操作必须解释原因；长期未实现能力不应通过禁用按钮进入正式界面。

## 07 长文、换行与截断

- 正文舒适行宽约 45—75 个中文字符；帮助内容不铺满超宽屏。
- 操作界面的说明优先 1—3 行，详细规则进入 Help、Drawer 或可展开说明。
- Heading 不截断；空间不足时换行或调整邻近控件。
- Button 文案原则上不换行；用更短的动词短语或移入菜单。
- 表格文本可截断，但必须可通过 Tooltip、详情或列宽调整读取完整值。
- 不用 Tooltip 承载必须阅读的安全、错误或删除说明。
- 不允许文字与图标重叠、被固定高度裁切或在 200% DPI 下消失。

---

## 08 可访问性与 DPI

- 普通文字最小 11 DIP；正文默认 13 DIP。
- 标准与大字号模式改变 token，不在页面局部放大。
- 100%、125%、150%、200% DPI 下行高必须随文字保持，不用固定像素高度裁切。
- 所有文本使用内容驱动或最小高度；多语言和较长中文文案须留 30% 宽度余量。
- 键盘焦点、错误文本和禁用原因不能只通过颜色差异表达。
- 屏幕阅读顺序：Heading → 说明 → 工具 → 内容 → 状态 / Footer。

---

## 09 禁止模式

- 页面内直接写 `FontSize`、`FontFamily`、任意 `LineHeight`；
- 9 或 10 DIP 小字；
- 将 Caption 用作主要正文；
- 每种卡片定义一个标题字号；
- 使用 Accent 颜色让普通标题“更重要”；
- 纯大写英文导航或长按钮；
- 用多个 FontWeight 微调出无法复用的层级；
- 文件名、路径和状态挤在图片上方形成控制台感；
- 用省略号隐藏错误原因、文件影响或不可逆操作。

---

## 10 实现契约

- 共享资源只暴露 `DisplayText`、`HeadingText`、`SectionText`、`BodyText`、`CaptionText`、`MetadataText` 和必要的 `NumericText`。
- Button、Menu、Input、Table 应从上述 token 继承，不复制字号。
- 所有固定高度控件必须通过 200% DPI 和大字号模式。
- 新文本角色必须说明为何六级系统不能表达，并先更新本文档。
