# Pixel Tart Image First Guideline v1.0

## 1. 首要规则

Pixel Tart 中，图片不是记录的附件；图片就是工作。任何图片相关页面都必须先设计图片观看与比较，再设计 Metadata 和控制器。

> 图片 > 空间 > 信息 > 控件

不得为了展示更多字段、筛选器、统计、分析参数或永久按钮牺牲图片。

## 2. 图片面积预算

- 素材库 Gallery：内容区宽度至少 65%，1920 宽舒适状态目标 70% 以上；
- Image Viewer：图片区域至少占 Viewer 可用面积 80%；
- 联机拍摄：最新照片/当前照片是最大单一对象；
- 工作台：首屏应有真实项目封面、最近素材或拍摄故事，不由统计卡占满；
- 项目：项目封面与代表作品必须先于表格和系统字段；
- 情绪板与策划中心：参考图持续可见，不退化为附件列表。

当不足时，按“收 Inspector → 收 Navigation → 收高级工具 → 减少 Metadata → 减少同屏数量”处理，最后才缩小图片。

## 3. 素材库

像数字暗房：

- 默认以缩略图视觉浏览，不以文字 List 开场；
- Grid、Masonry、Justified、List 共享选择与键盘语义，List 是特定整理任务而非默认；
- 缩略图保持比例，横竖幅可以自然混排；
- 顶栏只保留搜索、排序、视图和尺寸，高级筛选进入 Drawer；
- Inspector 克制，仅显示当前选择需要的信息；无选择收起；
- 双击进入独立 Viewer，而不是把大图塞进窄 Inspector；
- 分析、直方图、颜色检索与批处理按需打开，不永久占据右栏。

## 4. 灵感托盘

像桌上一叠照片：

- 必须显示缩略图，可横向胶片带、底部抽屉或轻量工作区；
- 支持快速加入、拖动重排、多选、移除与 Undo；
- 每项保留来源、标签与项目关联，但只在选择/Hover/Inspector 中展开；
- 来源失效用非颜色符号表达；移出托盘不删除原素材；
- 禁止用 AssetId、路径或纯文字列表替代图片。

## 5. 情绪板

必须是自由画布：

- 图片可移动、缩放、旋转、分层、分组；
- 支持文字、色板、注释和参考线，但图片保持最大视觉权重；
- 工具随选择出现，画布平移/缩放始终可用；
- 支持隐藏 Chrome 的整体观看模式；
- 删除画布元素不删除素材库源文件；
- 禁止固定列 Card 列表和表单式 Moodboard。

## 6. 策划中心

拍摄创作空间必须让概念与视觉参考同时存在：

- 概念、场景、灯光、造型、Shot List 均可关联参考图；
- Shot List 可通过缩略图理解顺序和目标，不是纯文字待办；
- 参考图可从素材库/灵感托盘拖入，使用稳定引用；
- 文字保持舒适行宽，图片不被缩成回形针附件；
- 不把所有创作内容强制进数据库式字段和等权 Card。

## 7. 项目与日历

- 项目列表使用真实封面或接触印相式预览；没有封面时提供安静占位与设置入口，不伪造图片；
- 项目详情用影像序列讲述工作进度，再补充 Booking、任务与交付信息；
- 工作日历让日期连接拍摄故事：`日期 → Booking → Project → Asset`；
- 月视图保持清楚，详情/日视图再出现项目封面和代表图片；
- 禁止项目只剩名称、金额、状态和操作列。

## 8. Thumbnail 质量

- 先显示可信 Preview，再渐进加载高质量缩略图；
- 使用统一 Thumbnail Provider，来源差异不改变视觉契约；
- 保留色彩配置与方向信息；不进行未声明的锐化、调色或裁切；
- Loading 保持宽高比，避免布局跳动；
- 缺失、离线、解码失败分别处理；
- 选择框绘制在图片之外；所有覆盖层合计不得遮挡主要内容。

## 9. Metadata 渐进披露

默认层只回答：这是什么、是否选中、与当前任务有什么关系。Hover 层提供一至三个快速动作。Inspector 提供完整信息。Dialog/专门工具才允许复杂编辑。路径、分析特征与内部 ID 不在缩略图下常驻。

## 10. 禁止清单

- 大量文字列表代替图片；
- 将图片统一裁成不符合任务的 Card 封面；
- 图片上常驻多排按钮、标签、路径和分析数据；
- 用空白黑块假装留白，却不给图片更大空间；
- 以“显示更多信息”为理由把 Gallery 压到次要区域；
- 使用装饰性样片、假项目或生成图掩盖 Empty State；
- 用 AI 发光框、自动取色主题或大面积状态色污染作品。
