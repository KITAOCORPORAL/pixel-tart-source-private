# Pixel Tart UI Review Checklist v1.0

使用方式：所有新页面、重大改版与公共组件变更在合并前逐项检查。`不适用` 必须写原因；任何“图片主体、源文件安全、键盘、Error、200% DPI”失败均阻断合并。

## A. 视觉

- [ ] 图片是否是页面主体，而非装饰或附件？
- [ ] 是否符合摄影工作室、暗房、编辑桌或档案馆气质？
- [ ] 是否有足够留白用于观看与判断？
- [ ] 颜色是否克制、中性，且只有一个品牌 Accent？
- [ ] 是否没有大面积渐变、蓝紫 AI 风、发光与彩色按钮堆积？
- [ ] 是否避免把所有内容做成 Card？
- [ ] 是否依靠排版和间距，而不是层层边框建立结构？
- [ ] 页面是否只有一个 Page Title 和一个 Primary Action？
- [ ] 六级字体角色是否清楚，没有页面自造字号？
- [ ] 图片周围的 UI 是否不会影响色彩判断？

## B. Image First

- [ ] 素材库 Gallery 是否至少获得内容区 65% 宽度？
- [ ] Viewer 图片是否至少获得可用面积 80%？
- [ ] Thumbnail 是否保持比例且不做未声明裁切？
- [ ] 图片 Loading 是否保持比例、渐进呈现且无布局跳动？
- [ ] Metadata 是否渐进披露，而非覆盖图片？
- [ ] 缺失、离线、解码失败是否可区分？
- [ ] Navigation/Inspector 空闲时是否能收起？
- [ ] 没有用大量文字列表替代图片？

## C. 交互

- [ ] Default、Hover、Active/Pressed、Focus 是否完整？
- [ ] Selected、Disabled、Loading 是否完整且不改变布局？
- [ ] Empty 是否说明一个明确下一步，不使用假数据？
- [ ] Error 是否说明发生了什么、源文件是否安全、如何恢复？
- [ ] Keyboard 是否覆盖进入、操作、退出与焦点返回？
- [ ] Esc、Enter、方向键、Menu Key/Shift+F10 行为是否符合组件契约？
- [ ] 焦点是否可见，Tab 顺序是否与视觉顺序一致？
- [ ] 长任务是否进入任务中心，可取消/重试/查看结果？
- [ ] 操作结果是否可预测，选择与滚动锚点是否保持？
- [ ] 可撤销动作是否提供 Undo，危险动作是否明确区分？
- [ ] Reduced Motion 下是否完整可用？

## D. 内容与状态

- [ ] 文案是否使用摄影工作流语言，而非企业后台/AI 营销话术？
- [ ] 未实现能力是否没有作为长期禁用入口展示？
- [ ] 日期、文件大小、分辨率、EXIF 格式是否统一？
- [ ] 状态是否不只依赖颜色？
- [ ] 空、离线、部分完成、失败与完成是否互不混淆？
- [ ] Tooltip 与可访问名称是否覆盖纯图标按钮？

## E. 布局与 DPI

- [ ] Margin、Padding、Gap 是否只使用 4px 系统 Token？
- [ ] 1080p 下是否无裁切，主要工作对象仍清楚？
- [ ] 2K/4K 是否把空间优先给图片，而非展开更多控件？
- [ ] 125%、150%、200% Windows DPI 是否通过？
- [ ] 200% + 长中文 + 大字号是否无截断/重叠？
- [ ] 控件目标高度是否至少 36 DIP，高频目标建议 40 DIP？
- [ ] 页面是否只有一个主要滚动区，滚轮路由正确？
- [ ] 小窗降级是否先收 Inspector/Navigation/低频工具？

## F. 组件

- [ ] Button 是否选对 Primary / Secondary / Ghost / Danger？
- [ ] Input 是否有外部 Label、错误原因与只读状态？
- [ ] Dropdown 是否支持键盘，长列表是否有搜索/Picker？
- [ ] Context Menu 是否按查看/整理/创作/项目/导出/危险分组？
- [ ] Dialog 是否短、可退出、只有一个主操作？
- [ ] Toast 是否不承担长任务与用户决策？
- [ ] Card 是否代表独立对象，且没有 Card 套 Card？
- [ ] Thumbnail / Viewer 是否遵守 Image First 契约？
- [ ] Inspector 是否只服务当前选择？
- [ ] Navigation 是否只回答“去哪里”？

## G. 工程

- [ ] 是否复用公共组件，而非复制页面内 Style？
- [ ] 是否只使用语义 Design Token，没有页面级 Hex/RGB？
- [ ] 是否没有新增旧版资源别名依赖？
- [ ] 是否没有破坏其他页面、主题或模块？
- [ ] Dark、Light、High Contrast 是否语义一致？
- [ ] 自动化标识是否稳定且不暴露给视觉层？
- [ ] 组件状态是否有自动测试或可重复人工证据？
- [ ] 是否检查运行截图，而非只审 XAML？
- [ ] 是否记录影响范围、迁移与回滚方式？

## H. 发布前证据

- [ ] 100%、125%、150%、200% DPI 截图；
- [ ] 1080p、2K 或等效工作区验证；
- [ ] Default、Loading、Empty、Error、长文本状态；
- [ ] 键盘完整路径与 Focus 截图；
- [ ] Dark、Light、High Contrast（适用页面）；
- [ ] 低性能/大量素材下 Thumbnail 渐进加载；
- [ ] 无源文件修改或危险动作确认的证据。

评审结论：`Pass / Conditional Pass / Blocked`。Conditional Pass 必须列出责任人、截止阶段和不影响用户的理由；阻断项不得以“后续统一修”跳过。
