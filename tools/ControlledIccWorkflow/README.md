# Controlled ICC Linear V1 — isolated experimental workflow

Not integrated into normal Color Studio UI. Default legacy path unchanged. External evaluated LCMS2.16 DLL is NOT distributed in product or tool packages; exact artifact SHA2f864b9f... is mandatory. Its acquisition/license/dependencies must be evaluated separately (see evidence02/03). Do not put arbitrary DLL/profile beside application to bypass the gate.

Build tools/ControlledIccWorkflow with workspace.NET10, then:

    ControlledIccWorkflow.exe inspect <real-JPEG-or-TIFF>
    ControlledIccWorkflow.exe --explicit-research <source-TIFF-or-JPEG> <new-result-directory> <absolute-evaluated-lcms2.dll> <working.icc> <output.icc>
    ControlledIccWorkflow.exe --native-selftest <absolute-evaluated-lcms2.dll> <linear-srgb.icc> <linear-prophoto.icc>

Positive input scope is presently the full Canon photographic linearRGB TIFF derivative generated by tools/controlled-icc/prepare_photo.py. No user RAW file is bundled/uploaded. It directly transforms actual embedded RTv4_sRGB to linear sRGB first, not assigns linear profile to encodedRGB. Original full-range ProPhoto roundtrip is REFUSED on output domain. Separate explicitly altered headroom fixture operation is recorded, not a correction to output. See evidence limits.

Allowed profiles exactly: linear-sRGB dafbff7207d22b526baa8f61a280e197b639af68cbe2e48529455157612b7407; linear-ProPhoto954e3bb304651951681989671ef99eed11183e9179a61a036243d655986c5ea1. Both test ICC files included in repository tests/TestData; only original math fixture profiles, not camera calibration profiles. No LUT, nonidentity TRC, CMYK/gray/alpha, orientation!=1, >50MP, missing/corrupt/not-evaluated profiles or nonrelative intent fallback. A readableunsupported profile still reports hash/version/space/reason with inspect. Output must be newdirectory, never overwrites source or oldrecipe.

Fixed recipe ControlledIccLinearV1 linear exposure-1EV, intent1/BPCoff/adaptation1; same detachedRGB48 preview and reloaded recipe produce identicalfloat output. TIFF16 and PNG16 compare exact integer codes with quantized preview and reread outputICC; JPEG8 separately lossy, metrics not a lossless-pass threshold. Output linear-sRGB has an ICC describing linearTRC, not implicitencodeddisplay sRGB. Physical calibratedscreen not tested. Tool writes version/input/output/workingSHA/domain/quantization in result.json; no accuracycorrected message.

PNG is an output-only validated format. JPEG source positive fixture/native UI and normal product ingress not verified. No default feature enable; PV456/PV7 unaffected. CalibrationEligible=false.
