# Company integration acceptance and launch tools

The normal App uses external company case contexts and private runtime roots. Run-AppGuard.py records one source-bound App with50ms samples and a2GiB guard; it checks the recorded process creation identity before reuse and does not inject application methods. Run-Service.py only starts/reuses configured local services; it does not rotate credentials or mutate bookings.

Start-OnlineSelection-LocalTest.ps1 preserves the established R3 service/App startup behavior with the explicit company desktopRoot and unique apphost. Both PowerShell versions were verified to reuse the same running App/service. A previous new launcher draft was unavailable and is not delivered.

No runtime databases, owner keys, device tokens, protected customer URLs or personal login URLs belong in Git or the package. Revalidate the package manifest before use. Normal UI/native picker receipts and automatic tests retain separate authorities. Camera/RAW, actual iPhone and ordinary40MP TIFF acceptance remain separately gated.

Seal-CompanyDiagnostic.py accepts --repo, --delivery-root and --source. It rejects existing archives, verifies all four compiled module versions and every archive-member digest, preserves historical source labels, and excludes known private runtime values. It does not claim native workflow or device acceptance from tests. Continue-CompanyPhone.cmd in the sealed package uses the existing prepared phone context after personal login; no booking or credential writes are performed by its HTTPS preflight.
